## Migration acceptance checks

1. **Registration integrity:** Retain the 37 CJSL and 3 EDP team registrations and their names, slugs, GotSport IDs, links, display overrides, and other event metadata.
2. **Input integrity:** All 40 original XLSX files remain available and paired with exactly one registered team. Unmodified files should retain their original Git blob IDs after moves.
3. **State continuity:** Preserve all 249 revision records, including per-match fingerprints, `sequence`, and `last_modified` values; preserve the EDP missing-match tracker and its safety policy.
4. **Feed continuity:** Generate 40 ICS feeds; inspect calendar `UID`, `SEQUENCE`, `LAST-MODIFIED`, and event counts against the original outputs. Do not accidentally reclassify an EDP disappearance as a confirmed cancellation. Keep CJSL explicit cancellation indicators.
5. **Publishing safety:** Never publish development-branch artifacts automatically. Verify `main` publishing behavior and GitHub Pages configuration before cutover.
6. **Index and URL transition:** Rebuild `docs/index.html`. Before switching published paths, document which calendar URLs change and how existing subscribers will resubscribe (or retain redirects/compatibility files if chosen).
7. **Recent updates:** Recompare the latest `main` against this snapshot immediately before merging; the original baseline may be stale while CJSL games are still being played.

**Important:** Matching file counts alone is insufficient. Before declaring success, compare content, identifiers, revision states, safety behavior, and the published link structure.
