## 6. New-chat handoff protocol

1. Before switching chats, update and commit the register with current branch, exact HEAD, status, tests, task IDs, next step, and outstanding review issues. If not ready to commit code, record uncommitted changes/diff and preserve them locally; never stage unrelated files blindly. Save a local copy of register and evidence archive; push only when authorized to the feature branch (not main). A local-only commit is not available to GitHub connector until pushed; attach the latest register in new chat regardless.
2. In new chat, attach latest register; optionally attach relevant diff/tests/audit ZIP or original reviews. Supply `git status --short --branch`, `git log -1 --oneline`, `git rev-parse HEAD`. Verify branch state and remote before edits. If a referenced file is unavailable, request only missing evidence, don't invent content. Use full repo bundle only if needed, not routinely.

Use one carefully verified step at a time; prefix Termux commands with clear;. No main edits/merges/publication without my explicit approval. Inspect actual files before commands. 4. Before final acceptance, compare all task IDs with the original review and all later external feedback, evidence and actual code. Explicitly approve any remaining deferred items. Never rely on chat history or memory alone.
